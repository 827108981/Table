## 🎯 项目简介

本系统是为 **迈瑞医疗中国区技术支持部门** 打造的**自动化实时监控大屏**。系统能够：

- 🤖 **自动爬取**企业内部 MSP 工单系统数据
- 📊 **实时展示**全国异常工单地理分布
- 🔊 **智能告警**语音播报紧急工单
- 📈 **趋势分析**24 小时异常工单变化趋势
- 📸 **一键截屏**方便汇报和分享

**核心价值**：将原本需要人工巡检的工单数据，转变为**实时可视、主动告警、数据驱动**的智能监控平台，帮助管理层第一时间发现和处理异常事件。

## ✨ 核心功能

### 🗺️ 全国工单实时地图
- 中国地图底色分区（华东/华北/华南/西南/西北五大区域着色）
- 异常工单以动态涟漪散点标注，**点位大小 = 超时严重程度**
- **颜色三级预警**：🔴 严重超时 (>72h) > 🟠 紧急超时 (48-72h) > 🟡 一般超时 (30-48h)
- **智能热点聚焦**：自动检测工单最密集的省份，地图平滑缩放聚焦，5 秒后恢复全国视图
- 鼠标悬停显示完整工单信息（医院、超时时长、工程师、产品、分公司、状态、创建时间）
- 密集点位自动偏移，避免重叠

### 📊 核心指标面板
| 指标 | 说明 |
|------|------|
| 异常工单总数 | 红色闪烁显示，醒目提示 |
| 平均超时时长 | 橙色显示，了解整体情况 |
| 最严重超时 | 红色闪烁，重点关注 |
| 涉及省份数 | 了解影响范围 |

### ⚠️ 最紧急 TOP5 列表
- 按超时时长降序排列，最紧急的工单永远在最上方
- 严重超时工单项带**呼吸灯闪烁动画**，吸引注意力
- 显示医院名称、服务工程师、超时时长

### 🔧 产品类型分布 (TOP5)
- 环形饼图展示各产品类型的异常工单占比
- 右侧图例显示产品名称和数量
- 超过 5 种产品时，其余自动归为"其他"类别

### 📈 24 小时趋势监控
- 折线图展示过去 24 小时异常工单数量变化
- 基于 LocalStorage 持久化存储
- 帮助发现异常高峰时段和趋势变化

### 📋 异常工单实时列表
- 包含排名、医院名称、产品类型、服务工程师、超时时长、状态
- **按紧急程度自动排序**，最严重的在最上面
- 严重超时行**持续闪烁高亮**
- **自动滚动**：每 6 秒向下滚动一行，到底部后回到顶部循环播放

### 🔊 智能语音播报
- 开启后自动播报最紧急工单信息
- 播报文案示例：*"紧急提醒，潜江市人民医院 工单已超时 86 小时，请 周海 立即处理"*
- **智能触发**：仅在超时恶化或超过 60 秒未播报时触发，避免频繁打扰
- 关闭后彻底静音，不会误报

### 🟢 数据新鲜度指示器
- 🟢 绿色：数据正常（< 5 分钟）
- 🟡 黄色：数据延迟（5-15 分钟）
- 🔴 红色：数据异常（> 15 分钟未更新）
- **点击可手动强制刷新**

### 📥 一键导出报表
- 点击即导出 CSV 文件（Excel 可直接打开）
- 包含完整工单信息：排名、医院、产品、工程师、超时时长、紧急程度、分公司、工单状态、创建时间
- 文件名带时间戳：`异常工单报表_20260411_2230.csv`

### 📸 一键截屏分享
- 自动截取整个大屏画面，高清 2 倍分辨率
- 自动下载为 PNG 文件，方便汇报和分享

### 🖥️ 全屏演示模式
- 一键进入浏览器全屏（类似 F11）
- 按 Esc 退出全屏
- 适合在指挥中心大屏上展示

### 🔴 滚动告警条
- 顶部红色横幅滚动显示最紧急的 TOP3 工单
- 类似新闻滚动条效果，24 小时不间断

### 数据流

```
MSP 工单系统 (https://msps.mindray.com/)
       │
       │  Playwright 浏览器自动化
       │  每 10 分钟自动抓取
       ▼
 工单报表_最新数据.xlsx  (原始数据)
       │
       │  openpyxl 读取 + 智能地理编码
       │  超时时长计算 + 紧急程度分级
       ▼
  hospital_data.json  (前端数据源)
       │
       │  HTTP 服务器 (端口 8080)
       ▼
  dashboard.html  (前端大屏)
       │
       │  每 15 秒自动轮询刷新
       ▼
  ECharts 地图 + 图表 + 表格 + 语音告警
```

### 线程同步流程

```
主线程
  ├── 启动数据爬取线程 (daemon)
  │     └── WorkOrderCrawler.init_browser()  (仅一次，启动浏览器)
  │     └── while True:
  │           ├── crawler.crawl()  (抓取数据)
  │           ├── data_ready_event.set()  (首次完成后通知前端启动)
  │           ├── data_updated_event.set()  (每次完成后通知数据处理)
  │           └── 等待 10 分钟 (600 秒)
  │
  └── 启动数据处理线程 (daemon)
        ├── data_ready_event.wait()  (阻塞等待首次数据)
        ├── extract_workorder_data()  (处理 Excel)
        ├── generate_hospital_json()  (生成 JSON)
        ├── start_http_server()  (启动 HTTP 服务)
        ├── open_browser()  (打开浏览器)
        └── while True:
              ├── data_updated_event.wait()  (等待新数据信号)
              ├── extract_workorder_data()
              └── generate_hospital_json()
```

## 🚀 快速开始

### 1. 安装依赖

```bash
# 进入项目目录
cd "/Users/bool/mindray/03 code/01_datacenter/01_code/git_test"

# 激活虚拟环境（如果已创建）
source .venv/bin/activate

# 如果没有虚拟环境，创建并激活
python3 -m venv .venv
source .venv/bin/activate

# 安装依赖
pip install -r requirements.txt

# 安装 Playwright 浏览器驱动
playwright install msedge
# 如果 Edge 不可用，使用 Chromium
playwright install chromium
```

### 2. 启动系统

```bash
python3 main.py
```

### 3. 首次运行流程

1. 系统启动后，会**自动打开 Edge 浏览器**访问 MSP 工单系统页面
2. **如果未登录**：
   - 在浏览器中手动输入账号密码完成登录
   - 切换到"工单报表"标签页
   - 设置筛选条件（如：工单状态=服务执行中-SR48，服务子类=维修-0301）
   - 回到终端**按回车键**确认
3. 程序开始自动抓取数据，完成后：
   - 自动处理数据并生成 `hospital_data.json`
   - 自动启动 HTTP 服务器（默认端口 8080）
   - **自动在新标签页打开数据大屏** `http://localhost:8080/dashboard.html`

### 4. 后续运行

- 浏览器会自动保持登录状态，**无需重新登录**
- 系统会**每 10 分钟自动抓取一次**新数据
- 大屏会**每 15 秒自动刷新**显示最新数据
- 全程自动化，无需人工干预

### 5. 停止系统

在终端按 **`Ctrl+C`**，系统会优雅地停止所有线程和服务器。

## 📖 功能详解

### 数据爬取 (`crawldata.py`)

| 功能 | 说明 |
|------|------|
| **浏览器复用** | 首次启动浏览器后保持打开，后续抓取复用同一实例，避免重复登录 |
| **登录状态检测** | 自动检测是否已登录，未登录时等待用户手动完成 |
| **手动筛选条件** | 首次运行时等待用户设置好筛选条件，后续全自动执行 |
| **自动点击执行** | 自动定位并点击"执行/查询"按钮触发数据查询 |
| **表格数据提取** | 支持多种表格结构解析（thead、tbody 首行、备用定位器） |
| **超时数据筛选** | 筛选创建时间超过 30 小时的工单，单独保存为 Excel |
| **定时循环** | 每 10 分钟自动重新抓取一次 |
| **日志记录** | 所有操作写入 `工单报表爬取日志.txt`，便于排查问题 |

### 数据处理 (`getHospital.py`)

| 功能 | 说明 |
|------|------|
| **Excel 解析** | 动态解析表头，自动匹配列索引，支持字段缺失容错 |
| **字段提取** | 工单号、服务工程师、产品型号、创建时间、预约完成时间、业务描述、分公司、工单状态 |
| **产品型号拆分** | 自动拆分为"产品类型"和"设备型号" |
| **医院地址提取** | 从业务描述中提取医院地址 |
| **超时时长计算** | 当前时间 - 创建时间 = 超时小时数 |
| **紧急程度分级** | critical (>72h)、urgent (48-72h)、warning (30-48h) |
| **智能地理编码** | 5 级降级策略（百度 API → 区县 → 城市 → 省份 → 默认） |
| **HTTP 服务器** | 自动查找可用端口，提供静态文件服务 |
| **浏览器自动打开** | 延迟打开，新标签页打开，不覆盖现有窗口 |

## ⚙️ 配置说明

### 主要配置项

| 配置项 | 位置 | 默认值 | 说明 |
|--------|------|--------|------|
| `WORKORDER_REPORT_URL` | `crawldata.py` 第 10 行 | Base64 编码 URL | MSP 工单报表系统地址 |
| `DATA_FOLDER` | `crawldata.py` 第 12 行 | `工单报表数据` | 数据存放文件夹名 |
| `BAIDU_AK` | `getHospital.py` 第 162 行 | `你的百度地图AK` | 百度地图 API Key |
| `USE_GEOCODING` | `getHospital.py` 第 163 行 | `True` | 是否启用百度地图地理编码 |
| 超时阈值 | `crawldata.py` 筛选逻辑 | 30 小时 | 筛选超时工单的时间阈值 |
| 紧急程度阈值 | `getHospital.py` | critical>72h, urgent>48h, warning>30h | 三级预警时间阈值 |
| 抓取间隔 | `main.py` | 600 秒 (10 分钟) | 每次数据抓取的间隔时间 |
| 前端刷新间隔 | `dashboard.html` | 15 秒 | 前端轮询 JSON 的间隔 |
| HTTP 端口 | `getHospital.py` | 8080 起 | HTTP 服务器起始端口 |

### 百度地图 API 配置（可选）

如果想获得更精确的地理定位（街道级别），请配置百度地图 API：

1. 访问 [百度地图开放平台](https://lbsyun.baidu.com/apiconsole/key)
2. 创建应用（选择"服务端"）
3. 复制访问应用（AK）
4. 打开 `getHospital.py`，找到第 162 行：
   ```python
   BAIDU_AK = "你的百度地图AK"
   ```
5. 替换为你的 AK

> **注意**：不配置 API 也可正常使用，系统会使用内置的区县/城市坐标映射（精度：5-50 公里）。

## ❓ 常见问题

### Q1: 程序无法启动？
**A**: 检查以下几点：
1. Python 版本是否 ≥ 3.9
2. 依赖包是否安装完整（`pip install -r requirements.txt`）
3. Playwright 浏览器是否已安装（`playwright install msedge`）
4. 是否有网络连接（首次需要下载浏览器组件）

### Q2: 数据大屏显示不出来？
**A**: 检查：
1. 是否已成功登录 MSP 系统
2. `hospital_data.json` 文件是否已生成
3. 浏览器是否支持 ECharts（需要现代浏览器）
4. 端口是否被占用（程序会自动从 8080 开始查找可用端口）

### Q3: 医院位置不准确？
**A**: 提升精度的方法：
1. 配置百度地图 API Key（最精确，误差 10-100 米）
2. 在 `district_coordinates` 中添加更多区县坐标
3. 检查地址格式是否规范

### Q4: 如何修改数据刷新间隔？
**A**:
- **后端爬取间隔**：修改 `main.py` 中的 `600`（秒）
- **前端刷新间隔**：修改 `dashboard.html` 中的 `15000`（毫秒）

### Q5: 如何修改超时判断规则？
**A**: 在 `crawldata.py` 的 `filter_timeout_data()` 函数中修改时间阈值（默认 30 小时），在 `getHospital.py` 中修改紧急程度分级阈值。

### Q6: 语音播报没有声音？
**A**:
1. 检查系统音量设置
2. 确保浏览器允许页面播放声音
3. 首次点击页面任意位置激活音频上下文
4. 使用 Chrome 或 Edge 浏览器（Safari 支持有限）

### Q7: 地图上的点位挤在一起？
**A**: 系统已自动对同位置点位进行偏移散开。如果仍然拥挤，可以：
1. 鼠标滚轮放大地图
2. 点击"热点聚焦"后地图会自动放大到问题省份

### Q8: 截屏功能无法使用？
**A**: 确保 `html2canvas` CDN 资源可以访问（需要网络）。如果离线环境，需要下载 `html2canvas.min.js` 到本地并修改引用路径。
